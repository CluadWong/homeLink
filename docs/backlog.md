  - 验收：记录板子地址与结果；不发送红外

  - 内容：选一个低风险设备，执行一次已学码功能
  - 验收：`status=sent`；审计有记录；用户人眼确认设备动作

- [ ] **B3 真机场景执行**
  - 内容：2 至 3 台设备的场景，执行后查看「最近执行」

- [ ] **B4 真机定时触发**

- [ ] **B5 真机失败面**

## C. P3 新组件加固（P1）

> 背景：场景 v3、调度器、执行记录都是近期新增，功能可用但运维面尚未补齐。

- [ ] **C1 `data/agent.db` 纳入备份与恢复**
  - 现状：`scripts/backup.py` 只备份 `homelink.db`
  - 动作：增加 `--agent-db` 或独立 `scripts/backup_agent.py`；`restore.py` 同步支持
  - 验收：备份后删除 `agent.db`，恢复后定时计划仍在

- [ ] **C2 `agent.db` schema 版本化**
  - 现状：`ScheduleStore` 用零散 `ALTER TABLE` 补列
  - 动作：引入 `PRAGMA user_version` 与迁移函数
  - 验收：旧库自动升级；版本不符时给出明确错误

- [ ] **C3 调度时区显式化**
  - 现状：`datetime.now()` 使用本机时区，无配置项
  - 动作：增加 `AGENTD_TZ`，或在文档中明确「本机时区」；补跨天与 DST 测试
  - 验收：时区行为可预测，边界测试覆盖

- [ ] **C4 单实例防重**
  - 现状：两个 daemon 同时运行会重复触发同一计划
  - 动作：文件锁，或文档明确「仅支持单实例」并在启动时检测
  - 验收：第二个实例拒绝启动或跳过执行

- [ ] **C5 调度失败可见性**
  - 现状：失败只写审计
  - 动作：前端明确展示 `last_status` 与失败原因；必要时本地告警
  - 验收：失败计划在界面上可见，不静默

- [ ] **C6 数据保留策略**
  - 现状：`device_states` / `audit_logs` 有保留期，`command_requests` 无
  - 动作：定义 `command_requests` 保留期与场景执行记录归档策略
  - 验收：长期运行数据库不无限增长；历史记录保留口径写进文档

- [ ] **C7 审计隐私**

  - 验收：文档明确敏感字段；轮转已覆盖（`rotate_logs.py` 支持 `.jsonl`）
