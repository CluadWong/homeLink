# 范围

## 定位

红外单向设备管家的后端：所有设备在运行期创建，学完码后按功能回放，并维护一份带可信度等级的虚拟状态。它不感知真实世界，只记录「我发出过什么、用户纠正过什么」。

## 运行边界

- 单进程：一个 FastAPI 服务 + 一个本地 SQLite 文件；无消息队列、无缓存中间件、无外部数据库。
- 一台主机接一个红外网关（ESPHome 板子），网关是唯一的外部硬件依赖。
- 状态、审计、配置审计落在同一个 SQLite 文件；重建版 schema 从 `SCHEMA_VERSION = 1` 起。
- 不联网、不调用云端模型、无 LLM 依赖；鉴权值只放在不入库的 `settings.local.yaml`。单用户、无登录：身份只区分 `user` / `system`。

## 范围内

1. 设备与房间的增删改查，含学码功能的删除；设备本期**不可启停**。
2. 设备全部由 `POST /api/devices` 在运行期创建，没有内置设备、没有配置种子。
3. 学码：建设备 → 开会话 → 轮询捕获 → 保存为功能 → 后续回放。
4. 调用：按 `function_id` 回放该功能最新一条码，固定走 `ir_proxy_tx`；没有参数与参数校验。
5. 设备状态：追加历史、重启恢复、按设备取最新，用户可手动校正。
6. 网关运维：mock/real 模式切换、地址配置、可达性探测（探测结果只用于展示）。
7. 审计：控制、学码、配置写入统一落库并可查询。
8. 过渡客户端：Streamlit 六页（调用/设备/学码/状态/校正/审计），仅作过渡。

## 范围外与归属

| 不做什么 | 归属 |
| --- | --- |
| 内置功能、能力（capability）、参数化控制、策略分级 | **本期放弃**：所有控制都是学码功能回放，不存能力表、不校验参数 |
| 场景、定时、规则引擎、意图理解与多轮对话 | 已下架；自动化与对话由上层智能管家实现，本服务只提供单次控制 |
| 温湿度等传感器 | **本期不接入**：`/api/state` 明确返回 `available=false` 与 `null`，界面显示「未接入」 |
| 用户体系与鉴权 | 单用户本地部署，暂不需要 |
| 正式前端 | 已完成：Vue 前端在 `frontend/` 实现，`frontend/dist` 构建通过并由后端同源托管，契约见 `frontend-contract.md`；Streamlit 保留但不参与启动 |

## 成功判据

1. 网关从 mock 换到 real 只改配置，核心代码零改动；mock 下无需硬件可跑通「建设备 → 学码 → 调用」全流程。
2. 进程重启后设备状态不丢，且绝不把 `unknown` 冒充 `confirmed`。
3. 每一次控制、学码、配置写入都能在 `audit_logs` 或 `config_audit` 中查到。
4. 学码半途退出（取消 / 超时 / 失败）不留下空壳设备，也不留下半条码。

## 关键取舍

- **状态是虚拟的**：红外无回传，回放后一律 `unknown`，只有用户校正才是 `confirmed`。
- **配置与运行期数据分离**：配置只留房间种子与网关；设备、功能、码、状态全部以库为权威。
- **单服务域**：不为未来多域提前抽象。
